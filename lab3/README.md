# Лабораторная работа №3 — Разработка алгоритма хэш-функции

Программа `myhash.py` реализует собственную хэш-функцию на основе функции варианта (таблица 3.1 методических указаний: 1 — sin(m), 2 — cos(m), 3 — xor(m)) и тесты из задания: эффект лавины, устойчивость к коллизиям с поиском пары, равномерность распределения.

## Запуск

```bash
python3 myhash.py sin      # или cos, xor
python3 myhash.py          # вариант спросит меню
```

## Схема хэш-функции

Итеративная схема с 64-битным внутренним состоянием (две 32-битные половины L, R) и 32-битным выходом (8 шестнадцатеричных цифр):

```
(L, R) ← (IV_L, IV_R)
для каждого символа с кодом c:   (L, R) ← (R, L xor F(R, c))     — раунд сети Фейстеля
выход ← fmix(L xor R xor длина)                                 — свёртка 64 → 32 и перемешивание
```

| Вариант | Функция варианта F(R, c) |
|---|---|
| sin / cos | t = (31·R + c) mod 2³², F = (round(sin(t)·2³⁰) mod 2³²) · 16777619 mod 2³² (для cos — аналогично) |
| xor | F = ((R xor c) · 16777619) mod 2³², затем F ← F xor (F >> 15) |

Обоснование решений:

- **Раунд сети Фейстеля обратим при известном символе**, поэтому шаг сжатия переставляет состояния, а не отображает их случайно: у случайного отображения на 32 битах длинные строки одинаковой длины сходились бы к общему состоянию, а вероятность коллизии на шаге была бы вдвое выше.
- **Односторонность** обеспечивает не sin/cos/xor (они обратимы), а свёртка 64-битного состояния в 32-битный выход: каждому значению хэша отвечает около 2³² состояний, прообраз и второй прообраз находятся только перебором ~2³², коллизия — за ~2¹⁶ попыток по парадоксу дней рождения. Длина выхода 32 бита выбрана намеренно: это делает выполнимым пункт задания «найти пару входов с одинаковым хэшем».
- **Значение sin квантуется** до целого round(sin(t)·2³⁰): математические библиотеки разных систем дают для больших аргументов значения, различающиеся в последнем бите double, и без квантования хэш зависел бы от платформы.
- Буквальное вычисление sin от всего сообщения как одного числа не годится: у double 53 бита мантиссы, и уже при 10 символах младшие символы перестают влиять на аргумент.
- Чистый xor кодов — 7-битный, коммутативный («ab» = «ba») и самообратный («aa» = пустая строка), поэтому в варианте xor добавлены умножение на простую константу и сдвиг.
- Соль приписывается к сообщению через разделитель, чтобы hash("abc") ≠ hash("bc", соль "a").
- Хэш принимает любые символы (по коду), а не только a–z, 0–9: функция переиспользуется в лабораторной работе №4 для текста ASCII.

Константы: IV_L = 0x811C9DC5 и P = 16777619 — из FNV-1a, IV_R = 0x9E3779B9 — 2³²/φ, финализатор fmix — из MurmurHash3.

## Режимы меню

1. Вычислить хэш сообщения (в том числе пустого), по желанию — с солью.
2. Эффект лавины: замена одного символа — оба хэша в шестнадцатеричном и двоичном виде, расстояние Хэмминга, статистика по 1000 случайным парам.
3. Устойчивость к коллизиям: структурные пары («ab»/«ba», «aa»/пустая строка, перенос символа в соль, «0»/«00») и поиск пары с одинаковым хэшем методом дней рождения по трём начальным значениям генератора (или заданному).
4. Равномерность: хэши 100 различных случайных сообщений — полный отсортированный список и распределение по 16 диапазонам (первая шестнадцатеричная цифра).
5. Сравнение с наивной схемой варианта (sin от суммы кодов / xor кодов) на тех же сообщениях.
0. Выход (также Ctrl+C / Ctrl+D).

Случайные сообщения генерируются с фиксированными начальными значениями, поэтому результаты тестов воспроизводимы.

## Результаты (одинаковы для трёх вариантов)

- Лавина: при замене одного символа меняется в среднем 16 бит из 32 (ожидание для идеальной функции — 16, разброс 6–26).
- Коллизия находится за 45–170 тысяч различных сообщений при теоретическом ожидании ≈ 82 тысячи (√(π/2 · 2³²)); все структурные пары дают разные хэши.
- 100 хэшей ложатся в 16 диапазонов без скоплений: максимум 9–12 при ожидании 6,25.
- Наивные схемы проваливают тесты: sin (cos) от суммы кодов коммутативен и даёт скопление 17–21 хэшей из 100 в одном диапазоне при ожидании 6, xor кодов меняет в среднем 3 бита из 32 и все хэши помещает в один диапазон.

## Использование в других работах

```python
from myhash import my_hash, to_hex
h = my_hash("текст", salt="", variant="sin")   # целое 0 ≤ h < 2**32
to_hex(h)                                       # строка из 8 шестнадцатеричных цифр
```
