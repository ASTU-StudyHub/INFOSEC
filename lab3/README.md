# Лабораторная работа №3 — Разработка алгоритма хэш-функции

Программа `myhash.py` реализует собственную хэш-функцию на основе sin(m) — вариант 1 по таблице 3.1 методических указаний — и тесты из задания: эффект лавины, устойчивость к коллизиям с поиском пары, равномерность распределения. Отчёт: `report.docx` / `report.pdf`.

## Запуск

```bash
python3 myhash.py
```

## Схема хэш-функции

Итеративная схема с 64-битным внутренним состоянием (две 32-битные половины L, R) и 32-битным выходом (8 шестнадцатеричных цифр):

```
(L, R) ← (IV_L, IV_R)
для каждого символа с кодом c:   (L, R) ← (R, L xor F(R, c))     — раунд сети Фейстеля
выход ← fmix(L xor R xor длина)                                 — свёртка 64 → 32 и перемешивание
```

Функция раунда F(R, c) построена на sin:

```
t = (31·R + c) mod 2³²
F = (round(sin(t)·2³⁰) mod 2³²) · 16777619 mod 2³²
```

Обоснование решений:

- **Раунд сети Фейстеля обратим при известном символе**, поэтому шаг сжатия переставляет состояния, а не отображает их случайно: у случайного отображения на 32 битах длинные строки одинаковой длины сходились бы к общему состоянию, а вероятность коллизии на шаге была бы вдвое выше.
- **Односторонность** обеспечивает не sin (на отрезке монотонности он обратим через arcsin), а свёртка 64-битного состояния в 32-битный выход: каждому значению хэша отвечает около 2³² состояний, прообраз и второй прообраз находятся только перебором ~2³², коллизия — за ~2¹⁶ попыток по парадоксу дней рождения. Длина выхода 32 бита выбрана намеренно: это делает выполнимым пункт задания «найти пару входов с одинаковым хэшем».
- **Значение sin квантуется** до целого round(sin(t)·2³⁰): математические библиотеки разных систем дают для больших аргументов значения, различающиеся в последнем бите double. Без квантования хэш зависел бы от платформы при любом таком расхождении, после квантования — только в редком случае, когда sin(t)·2³⁰ близко к полуцелому числу.
- Буквальное вычисление sin от всего сообщения как одного числа не годится: у double 53 бита мантиссы, и уже при 10 символах младшие символы перестают влиять на аргумент.
- Соль приписывается к сообщению через разделитель, чтобы hash("abc") ≠ hash("bc", соль "a").
- Хэш принимает любые символы (по коду), а не только a–z, 0–9: функция переиспользуется в лабораторной работе №4 для текста ASCII.

Константы: IV_L = 0x811C9DC5 и P = 16777619 — из FNV-1a, IV_R = 0x9E3779B9 — 2³²/φ, финализатор fmix — из MurmurHash3.

## Режимы меню

- **1** — вычислить хэш сообщения (в том числе пустого), по желанию — с солью.
- **2** — эффект лавины: замена одного символа — оба хэша в шестнадцатеричном и двоичном виде, расстояние Хэмминга, статистика по 1000 случайным парам.
- **3** — устойчивость к коллизиям: структурные пары («ab»/«ba», «aa»/пустая строка, перенос символа в соль, «0»/«00») и поиск пары с одинаковым хэшем методом дней рождения по трём начальным значениям генератора или по заданному целому (на ввод, не являющийся целым числом, программа сообщает об ошибке и выполняет три запуска по умолчанию).
- **4** — равномерность: хэши 100 различных случайных сообщений — полный отсортированный список и распределение по 16 диапазонам (первая шестнадцатеричная цифра).
- **5** — сравнение с наивной схемой floor(|sin(сумма кодов)|·2³²) на тех же сообщениях: лавина, максимум хэшей в диапазоне, структурные коллизии.
- **0** — выход (также Ctrl+C / Ctrl+D).

Случайные сообщения генерируются с фиксированными начальными значениями, поэтому результаты тестов воспроизводимы.

## Результаты

- Хэши: пустая строка — `4a216c31`, «abc» — `7139aeec`, «abc» с солью «s1» — `c75fe06f`; хэш любого входа (от пустого до 10 000 символов) — ровно 8 шестнадцатеричных цифр.
- Лавина: при замене одного символа меняется в среднем 15,92 бита из 32 по 1000 случайным парам (ожидание для идеальной функции — 16, минимум 6, максимум 26).
- Коллизия находится за 89 364, 146 559 и 76 699 различных сообщений (seed 2026, 1, 2; в среднем 104 207) при теоретическом ожидании ≈ 82 137 (√(π/2 · 2³²)); например, «dmr75y» и «69ny4tv5t8k9» дают хэш `cda8d68e`. Все структурные пары дают разные хэши.
- 100 хэшей ложатся в 16 диапазонов без скоплений: от 3 до 12 в диапазоне при ожидании 6,25.
- Наивная схема sin от суммы кодов при сходной лавине (15,8 бита против 15,9) коммутативна («ab» и «ba» дают один хэш) и даёт скопление 21 хэша из 100 в одном диапазоне, итоговая схема — не больше 12.
