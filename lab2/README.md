# Лабораторная работа №2 — Алгоритм шифрования RSA

Программа реализует генерацию ключей, шифрование и расшифрование по алгоритму RSA для текста из символов ASCII. Файлы: `rsa.py` — программа, `report.docx` / `report.pdf` — отчёт.

## Запуск

```bash
python3 rsa.py
```

## Режимы меню

- **1 — случайные ключи**: p, q — случайные простые из [100, 9999]; d — случайное, взаимно простое с φ = (p − 1)(q − 1); e вычисляется из условия e·d mod φ = 1 (обозначения методических указаний: открытый ключ {e, n}, закрытый {d, n}).
- **2 — ввод ключей вручную** p, q, d с проверками: p, q — простые, различные и не больше 10¹², n = p·q ≥ 256, 1 < d < φ, НОД(d, φ) = 1. При неверном значении выводится сообщение и запрос повторяется.
- **3 — шифрование текста** открытым ключом: каждый символ — отдельный блок M = код символа, C = Mᵉ mod n; шифртекст выводится как числа через пробел.
- **4 — расшифрование** закрытым ключом {d, n} по введённым числам. Enter вместо d — текущий закрытый ключ {d, n} целиком (n не запрашивается), иначе вводятся d и n; Enter вместо шифртекста — последний результат пункта 3. Каждое число шифртекста, в том числе последнего результата, проверяется на диапазон [0, n − 1].
- **5 — самопроверка**: пример методических указаний (p = 3, q = 11, d = 3 → e = 7; блоки 3, 1, 2 → 9, 1, 29 → 3, 1, 2) и прогон всех кодов 0..255 через ключ с n = 265.
- **6 — вычисление закрытого ключа по открытому**: разложение n на множители пробным делением, φ, d = e⁻¹ mod φ — иллюстрация к вопросу о стойкости. При больших n разложение может занять много времени; Ctrl+C прерывает его и возвращает в меню, ключи сохраняются.
- **0 — выход** (также Ctrl+C / Ctrl+D при вводе).

## Особенности реализации

- Порог n ≥ 256 взят с запасом: любой байт 0..255 меньше n, а для кодов ASCII 0..127 хватило бы n ≥ 128. Пример методических указаний с n = 33 на числах 1, 2, 3 воспроизводится, а на кодах ASCII (65–67) даёт M mod 33.
- При ручном вводе p и q ограничены значением 10¹²: простота проверяется пробным делением (не больше 5·10⁵ делений), и для больших чисел проверка заняла бы минуты и часы.
- Текст вводится одной строкой, поэтому символ перевода строки (код 10) в него не входит; работа шифрования со всеми кодами 0..127 подтверждается самопроверкой (пункт 5).
- Условие p ≠ q обязательно: при p = q формула φ = (p − 1)(q − 1) неверна. Составное p ломает расшифрование без сообщения об ошибке, поэтому простота проверяется в коде (пробное деление).
- Обратный элемент e = d⁻¹ mod φ находится расширенным алгоритмом Евклида (`egcd`, `modinv`), возведение в степень — бинарным методом по модулю (`modpow`): вычислять Mᵉ целиком нельзя, при четырёхзначных p, q это число из миллионов цифр.
- При расшифровании чужим или неверным ключом блок может не быть кодом символа — программа сообщает об этом, а не завершается с ошибкой.

## Результаты

- Пример методических указаний воспроизведён; при n ≥ 256 все 256 кодов проходят цикл шифрование → расшифрование без искажений, при n = 129 — только 129 кодов из 256 (0..128): все коды ASCII 0..127 проходят, байты 129..255 — нет.
- Восемь наборов ручного ввода: корректные пары приняты, составное p, p = q, n < 256, НОД(d, φ) ≠ 1 и нечисловой ввод отклонены.
- Время шифрования 100 символов: наивное возведение целиком — 32 с при трёхзначных простых, бинарный метод — 0,2 мс.
- Закрытый ключ по открытому для n ≈ 10⁸ вычисляется за 0,2 мс: стойкость учебных ключей отсутствует, в реальных системах используются n длиной 2048 бит и более.
