# Лабораторная работа №4 — Реализация электронной цифровой подписи

Программа подписывает текстовое сообщение электронной цифровой подписью (ЭЦП) на основе RSA, проверяет подпись и показывает, что изменение подписанного сообщения обнаруживается. Файлы: `signature.py` — программа, `report.docx` / `report.pdf` — отчёт.

## Запуск

```bash
python3 signature.py
```

Программа использует модули предыдущих работ: `../lab2/rsa.py` (RSA) и `../lab3/myhash.py` (собственная хэш-функция на основе sin(m), вариант 1 ЛР3). Папки `lab2` и `lab3` должны лежать рядом с папкой `lab4`; модули находятся по расположению `signature.py`, поэтому текущий каталог при запуске не важен.

## Схема

```
формирование:  h = H(M);  S = h^d mod n;   передаётся пара (M, S)
проверка:      h' = H(M); h'' = S^e mod n;  подпись верна, если h' = h''
```

Закрытый ключ `{d, n}` есть только у автора — аутентичность и неотказуемость; открытый `{e, n}` — у всех — проверяемость; любое изменение M меняет h' — целостность.

## Режимы меню

- **1 — ключи RSA.** Случайные (p, q — простые из [2¹⁷, 2¹⁸)) или ввод p, q, d вручную с проверками: p, q — простые, не больше 10¹², различные, p·q > 2³²; перед вводом d выводятся n и φ, условия на d — 1 < d < φ и НОД(d, φ) = 1 (Enter — случайное d). При неверном значении выводится сообщение с причиной и запрос повторяется.
- **2 — сообщение** с клавиатуры (строка ASCII, в том числе пустая) или случайное из печатных символов ASCII заданной длины.
- **3 — подпись.** Выводятся h (в шестнадцатеричном и десятичном виде), S и передаваемая пара (M, S).
- **4 — проверка подписи** текущей пары, изменённого сообщения с той же S или введённых M и S.
- **5 — модификация подписанного сообщения** с проверкой сразу после изменения: замена, вставка, удаление символа или перестановка соседних символов — с выбором позиции и символа или случайно.
- **6 — автотест** на 1000 случайных сообщений.
- **7 — демонстрация условия h < n** на ключах из примера ЛР2 (n = 33).
- **0 — выход** (также Ctrl+C / Ctrl+D).

## Особенности реализации

- **Условие h < n.** Хэш из ЛР3 32-битный, а проверка восстанавливает лишь `h mod n`: при h ≥ n подпись не сходится даже на нетронутом сообщении, а при n < 2³² такое h возможно. Поэтому простые p, q берутся из [2¹⁷, 2¹⁸): n = p·q ≥ 2³⁴ > 2³². Пункт меню 7 показывает это на ключах из примера ЛР2 (n = 33).
- **Модификация без пересчёта подписи** — модель злоумышленника в канале: замена, вставка, удаление, перестановка соседних символов, вручную или случайно. При проверке выводится число различающихся бит хэш-сумм.
- **Сообщение** — любой текст ASCII (коды 0..127), включая пустой; ввод однострочный, поэтому перевод строки (код 10) с клавиатуры не вводится. Случайные сообщения и замены составляются из печатных символов (коды 32..126).
- **Проверка ввода.** Ответ подменю, которого нет среди предложенных вариантов, отклоняется сообщением «Нет такого варианта» с повтором вопроса. Вид модификации, невозможный для данного сообщения (удаление или замена в пустом, перестановка в сообщении без соседних различных символов — например, «a» или «aaa»), не принимается; позиция перестановки — от 0 до длины минус 2, одинаковые соседние символы переставить нельзя, а случайная позиция перестановки выбирается только среди пар различных символов.
- **Предел 10¹² для p и q** при ручном вводе — как в ЛР2: простота проверяется пробным делением, и для больших чисел проверка заняла бы минуты и часы.
- **Автотест**: 1000 случайных сообщений длины 0–50 — нетронутые проходят проверку, изменённые отклоняются (ожидается 1000/1000 в обоих случаях).

## Результаты

- Нетронутые сообщения: 1000/1000 проверок пройдено; изменённые: 1000/1000 отклонено.
- При замене одного символа хэш-суммы h' и h'' различаются в среднем на 16 бит из 32 (лавинный эффект хэша ЛР3).
- Ключи n = 33: h = 3264597241 ≥ n, S^e mod n = h mod n = 4 ≠ h — проверка нетронутого сообщения не сходится.
