# Лабораторная работа №5 — Комплексное обеспечение безопасности менеджера учётных записей

Программа с графическим интерфейсом (Python 3, стандартная библиотека, tkinter):

```bash
python3 lab5/manager.py            # окно менеджера; файлы данных — в lab5/data/
python3 lab5/manager.py ПАПКА      # другая папка данных
python3 lab5/storage.py            # автоматическая проверка всех подсистем без GUI
python3 lab5/aes.py                # проверка шифра на тестовых векторах FIPS-197
```

Модули: `manager.py` — окно и диалоги; `storage.py` — учётные записи, целостность, шифрование файлов, журнал; `aes.py` — собственная реализация AES (FIPS-197) в режиме CBC. Сторонние пакеты не используются.

## Файлы данных

| Файл | Содержимое |
|---|---|
| `accounts.txt` | БД: строка `логин:соль(hex):хэш(hex)` на каждую учётную запись, пароли в открытом виде не хранятся |
| `accounts.hash` | эталонная хэш-сумма SHA-256 файла БД, формат `хэш  accounts.txt` |
| `events.log` | журнал событий: `ГГГГ-ММ-ДД ЧЧ:ММ:СС  событие` |

## Подсистемы защиты

1. **Хэширование паролей.** Для каждой записи своя случайная соль (16 байт), хэш — PBKDF2-HMAC-SHA256 (100 000 итераций). Проверка пароля: хэш пересчитывается с сохранённой солью и сравнивается с записанным (`hmac.compare_digest`). Одинаковые пароли у разных пользователей дают разные хэши, радужные таблицы бесполезны, перебор замедлен в 10⁵ раз.
2. **Целостность БД.** При каждом изменении БД через программу (добавление, изменение, удаление) её SHA-256 записывается в `accounts.hash`. Кнопка «Проверить целостность» сравнивает актуальную хэш-сумму с эталонной: «БД в целостности» или «БД была изменена извне» (например, после правки `accounts.txt` в текстовом редакторе). Кнопка «Сохранить хэш-сумму» принимает текущее состояние за эталон. Если файл БД удалён извне, а эталон остался, программа не создаёт БД заново молча: проверка сообщает об удалении, а пустую БД можно создать явно кнопкой «Добавить».
3. **Шифрование файлов.** Каждый из трёх файлов шифруется и расшифровывается отдельно, по паролю (ключу) файла. Ключ шифрования и ключ HMAC выводятся из пароля функцией PBKDF2-HMAC-SHA256 (200 000 итераций) со случайной солью, в соль входит и имя файла — у файлов заведомо разные ключи. Формат: строка-признак, затем base64(соль | IV | AES-256-CBC(данные) | HMAC-SHA256). HMAC проверяется до расшифрования, поэтому неверный пароль или повреждение файла обнаруживаются сразу, а не дают «мусор».
4. **Журнал событий.** Дата и время записываются для добавления, изменения и удаления учётных записей, проверки пароля, шифрования и расшифрования каждого файла (включая отказ при неверном ключе к БД и файлу хэш-суммы; отказ по самому журналу записать некуда — он в этот момент зашифрован), сохранения и сравнения хэш-суммы.

**Шифрование не конфликтует с целостностью:** хэш-сумма считается по открытому содержимому БД, а шифрование обратимо байт в байт, поэтому после расшифрования проверка сходится. Пока файл зашифрован, операции с ним недоступны (список записей и хэш-суммы показывают «зашифрован»). БД и эталон меняются только вместе: если после записи БД не удалось записать хэш-сумму или журнал, БД возвращается к прежнему содержимому. Все операции регистрируются в журнале, поэтому при зашифрованном журнале доступно только его расшифрование — принцип «нет журнала — нет операции».

## Окно программы

- **Учётные записи** — таблица логин / соль / хэш; кнопки «Добавить», «Изменить» (переименование и/или новый пароль), «Удалить», «Проверить пароль», «Обновить» (перечитать файлы с диска).
- **Шифрование файлов** — для каждого файла состояние (открыт, размер / ЗАШИФРОВАН) и кнопки «Зашифровать» (пароль вводится дважды) и «Расшифровать».
- **Целостность БД** — эталонная и актуальная хэш-суммы, кнопки «Сохранить хэш-сумму» и «Проверить целостность».
- **Журнал событий** — содержимое `events.log` целиком, обновляется после каждой операции.

Ошибки (дубликат логина, пустой пароль, неверный ключ файла, зашифрованный или повреждённый извне файл, отсутствие прав на запись) показываются в диалоговых окнах; строка состояния внизу дублирует результат последней операции.

## Результаты

- `storage.py`: 25/25 проверок — пароли не хранятся открыто, верный/неверный пароль различаются, дубликаты и логины с «#» отклоняются, внешняя правка БД обнаруживается, испорченные файлы БД и хэш-суммы дают сообщение об ошибке, после шифрования файлы нечитаемы, операции с зашифрованными файлами блокируются, неверный ключ отвергается, после расшифрования БД в целостности, в журнале есть все виды событий.
- `aes.py`: шифртексты совпадают с тестовыми векторами FIPS-197 для AES-128/192/256, режим CBC обратим на данных длиной 0–1000 байт.
